# Managed ACP adapters

Codex and Claude adapters are prepared on the first model probe or session creation when their base CLI exists. Explicit Install/Update uses the same implementation. npm receives an explicit prefix and cache under `~/.local/share/remote-codex/adapters`; it never changes the account's npm configuration or requires sudo. Existing external installations remain usable; explicit adapter updates select the managed installation.

Detection, management/version inspection, model commands and ACP startup resolve executables through one resolver. Managed binaries win, followed by the inherited PATH and known user installation directories. Child processes receive the same search path on each launch, including directories created after Supervisor startup. Startup uses the resolved absolute executable, with original arguments preserved. A successful installer must produce an executable in the managed prefix.

Settings always displays the adapter for adapter-based harnesses. A missing adapter has an Install action; older devices returning null retain a repair entry using their existing install endpoint (they require a runtime update for managed-prefix installation). Base update completion does not imply ACP readiness. Explicit adapter installation verifies an ACP session using bounded protocol requests, and distinguishes installation failure from authentication/protocol failure. Agent metadata now reports observed versions and paths, plus last ACP verification status/error. `availability: ready` retains its legacy binary-availability meaning; visible Ready/verified status requires a successful ACP session.

Automatic installation is serialized within the Supervisor and failed attempts back off for 60 seconds. Manual installation retries immediately. Every automatic retry checks executable discovery before the backoff, so an external installation becomes usable immediately without restarting. Existing durable queue retries continue with their stored message; errors include the executable, package and Settings repair location. Failed/cancelled ACP startup and probes shut down temporary processes.

Validation: focused runtime ACP regressions, management UI regressions (including old null-adapter responses), Web typechecking, and the [Ubuntu 24.04 regression](../e2e/managed-adapters/README.md). The Ubuntu check uses real npm/Codex/adapter and a local model-response fixture; it verifies original queued input executes once after a previously undiscoverable user-prefix installation. No production Supervisor is restarted by these checks.
